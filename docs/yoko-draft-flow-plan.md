# YOKO投稿作成フローの開発計画

2026-09-12。Serena MCPでANALYCAの関数と呼び出し元を確認した上で実施。

## 対応する2経路

1. 完成タブ限定の「投稿作成」から、手動原稿を直接完成へ保存する。
   メイン・コメント1・2は必須、各500文字以内。テーマは省略可能。
   文体AIは実行せず、既存のLINE選択・プレビュー・送信へ接続する。
2. AI文体変換は、初回変換に加え最大2回の修正・再監査を行う。
   合格した投稿は再変換しない。内容の正本は採用原文に固定する。
   再監査に元台本の内容を持ち込まず、本人実文は文体の根拠に限る。

## 変更箇所

- app/[userId]/components/threads-content-creation-tab.tsx:
  完成タブの作成フォーム、保存・一覧更新、既存NG稿の明示的なAI再調整。
- app/api/threads/content-drafts/route.ts:
  手動完成稿を作成するPOST。対象アカウント・入力検証。
- app/api/threads/content-drafts/style/route.ts:
  既存修正稿を明示的に再調整するフラグ、処理件数の制限。
- lib/threads-content-drafts.ts:
  手動完成稿の保存、文体修正パイプラインとの接続、利用量記録。
- lib/yoko-manual-draft.ts / lib/yoko-style-pipeline.ts:
  入力検証と再試行処理を外部サービスから分離し、モックで検証する。
- lib/__tests__/:
  直接作成の入力、NGのみ再試行、合格済み稿の保持、修正上限、監査失敗を検証。

## 保持する動作

- メイン投稿は文体変換の対象外。
- 手で修正された既存稿は、利用者がAI再調整を選ぶまで書き換えない。
- 自動修正後も合格しない投稿を、自動的に完成・送信にはしない。
- 文体確認から完成へ進める判断、LINEの送信確認は人が行う。
- 既存の予約・送信済みデータと無関係な作業ツリー変更は触らない。

## 検証と反映

1. サービスをモックしたテストと既存関連テスト。
2. lint / 型チェック / production build。
3. ローカル画面で完成限定の作成フォームと入力検証を確認。
4. 変更ファイルだけをmainへcommit・push。
5. GitHub連携の本番デプロイ完了とcanonical画面・APIを確認。
   本番の投稿作成・文体変換・LINE送信は検証目的で勝手に実行しない。
